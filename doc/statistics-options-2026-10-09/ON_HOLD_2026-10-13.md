## Reader design findings

Use Pydantic models for manifests and rows. Verify account, configuration, date,
schema version, file size and checksum; support gzip. `record_value` is URL
encoded. Bucket metrics contain both empty storage-class aggregate records and
storage-class-specific records: do not sum both. Preserve dimensional keys and
prefer authoritative aggregate rows. Never sum parent prefixes with descendants
or add repeated daily exports. Represent absent/delayed dates as missing.

On October 12, the default CSV contained 4,721 records. One inspected expanded
shard contained 23,256 prefix records for other buckets; the whole manifest has
six shards. Read all shards, filter to the requested corpus bucket, and validate
that expected categories are present. Do not treat a nonmatching shard as zero
corpus activity. GET counts include repeated and range requests. Unique objects
accessed are not completed downloads; native metrics do not identify bots.
[AWS manifest schema](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage_lens_whatis_metrics_export_manifest.html),
[AWS export schema](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage_lens_understanding_metrics_export_schema.html).

The existing reports page is `https://search.digitalcorpora.org/reports`.
`stats.digitalcorpora.org` did not resolve during this check. Validate the intended
hosting path before publication and preserve old report links where useful.
